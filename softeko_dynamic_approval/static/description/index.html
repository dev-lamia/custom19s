OVERVIEW

Approvals where the work happens

Protect the exact business action—Confirm, Validate, Send, Post or Delete—right on the document your team already uses.

Protect Any Button

Any object button on a form—Confirm, Validate, Send, Post—plus Delete.

Automatic Button Discovery

Buttons are read from the model’s form views, including inherited ones. Refresh any time.

Multi-Level Approvers

Add as many approvers as you need, set their order and mark each one required or optional.

Sequential or Parallel

Approve one after another, or let approvers act in any order with a minimum count.

Conditional Rules

Apply a rule only when a domain matches—for example, orders above 50,000.

Initiators & Companies

Limit who triggers a rule and which companies it applies to.

Activities & Chatter

Approvers get a To-Do on the document itself; every step is noted in the chatter.

Re-approval on Reset

Cancelling a document or resetting it to draft retires the used approval automatically.

HOW IT WORKS

From click to approved action

Approval and execution are two deliberate clicks, so nothing runs before sign-off.

STEP 1

Click the button

If a rule matches, the action is paused and request APR/xxxxx is created.

STEP 2

Approvers notified

The first approver—or every approver in parallel mode—gets a To-Do on the document.

STEP 3

Approve on the document

For the approver whose turn it is, the same button reads Approve.

STEP 4

Approval completes

Required approvers and the minimum count reached; the initiator gets an Approval Completed activity.

STEP 5

Run the action

The initiator clicks the original button again—it runs natively, tracking included.

RULE FIELDS

What each setting does

ModelAny business object, e.g. Sales Order, Purchase Order, Journal Entry, Transfer or Lead.
Button / ActionPicked from the buttons found on that model’s form views, plus Delete.
PriorityOrder in which rules are evaluated when several could apply.
Applicable CompaniesEmpty = every company. Select companies to limit the rule.
Allowed InitiatorsEmpty = every internal user. Select users to make the rule apply only to them.
ApproversOrdered list of users; switch Required off for optional approvers.
Approve by SequenceOn: one after another. Off: any order.
Minimum ApprovalsTotal approvals needed. Required approvers must always approve.
Condition DomainOptional filter on the record, e.g. amount_total > 50000.

CONTROLS

Built-in safeguards

Approvals that can’t be bypassed, with Odoo’s standard behaviour left intact.

Approval activities can’t be skipped

“Approval Required” activities can’t be marked done, edited or cancelled from the chatter—only Approve completes them. Administrators keep full control.

Activities stay with their owner

Other activities can be marked done only by the assigned user or an administrator.

Role-based access

Dynamic Approval Manager configures rules and sees every request. Users see only requests they started or need to approve.

Native tracking preserved

The protected method runs through Odoo’s normal write chain, so field tracking and chatter messages stay standard.

Always enforced

Protection is re-applied when the server starts and on every worker, so a restart never lets a button skip approval.

Smart rule matching

Rules for specific initiators first, then company-specific rules; rules whose condition matches win over catch-all rules.

Reject or cancel

Any assigned approver can reject; managers can cancel a pending request. Both close the open approval activities.

One approval, one cycle

An approval stays valid until the document is cancelled or reset to draft—then a fresh approval is required.

GET STARTED

Three quick steps

  1. Install Dynamic Approval from Apps.
  2. Give the people who set up rules the Dynamic Approval Manager group (Settings › Users).
  3. Open Dynamic Approval › Configuration › Approval Rules, choose the model and button, add approvers and save—the rule is active immediately.
QUICK ANSWERS

Frequently asked questions

Do I need the Odoo Approvals app?

No. Dynamic Approval is standalone, with its own rules and requests. It only depends on standard Odoo apps (Sales, Purchase, Invoicing, Inventory, CRM).

Which buttons can I protect?

Object buttons on the selected model’s form views—including buttons added by other modules—plus public action_… / button_… methods and Delete. Click Refresh Available Buttons after installing new apps.

What happens after the final approval?

The initiator gets an “Approval Completed” activity and the original button shows again. Clicking it runs the action normally. The approval stays valid until the document is cancelled or reset to draft.

Can one button have different approvers?

Yes. Create several rules for the same button with different conditions, companies or initiators. The most specific matching rule is used, ordered by priority.

What if an approver rejects?

The request becomes Rejected, open approval activities are closed and a note is posted on the document. Clicking the button again starts a new request.

Where can I follow requests?

Open a rule and use its Requests smart button. Each request shows approver progress and links back to the source document.

Does it change how normal activities work?

Yes, slightly: users who are not administrators can mark done only the activities assigned to them, and approval activities can only be completed through Approve.
